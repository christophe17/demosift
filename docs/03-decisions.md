# Decisions

Short records, newest last. A decision is changed by a new entry, not by editing an old one.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-09-21 | Name the project **demosift** | "Demos" is the community's word for demonstrations, "sift" is sorting good from bad; free on PyPI, one homonymous repository on GitHub |
| D2 | 2026-09-21 | Python 3.12, `uv`, a single `src/` package | One package is enough until a second deployable exists; `uv` gives a lock file and fast CI |
| D3 | 2026-09-21 | Region `eu-central-1`; default model `eu.anthropic.claude-sonnet-5` through the EU cross-region profile | AgentCore and the EU inference profiles were verified available there on 2026-09-18 for the author's previous project; EU data residency for a European author |
| D4 | 2026-09-21 | Read LeRobot codebase **v3.0 only**; refuse other versions with an explicit error | The Hub's current format; supporting v2.1 doubles the reader for datasets that are being migrated anyway. Revisit when a user asks |
| D5 | 2026-09-21 | Deterministic core, models narrate | A report whose numbers come from a model cannot be trusted or tested; the inspection is code, the model writes prose over it |
| D6 | 2026-09-21 | Apache-2.0 | The licence of LeRobot and of most of the ecosystem; permissive, with a patent grant |
| D7 | 2026-09-21 | Download only `meta/` at milestone 0 | Metadata weighs kilobytes, data and videos weigh gigabytes; frame-level audits will download selectively |
| D8 | 2026-09-21 | Strands Agents as the agent framework, the `bedrock_agentcore` SDK for the Runtime contract | Both are AWS's first-party choices for AgentCore; the author already knows them |
| D9 | 2026-09-21 | GitHub organization **undecided**; the repository starts under the author's personal account | No organization exists yet; moving a repository later keeps its history and redirects |
| D10 | 2026-09-21 | Terraform layout inherited from `cgp-ai`: `modules/` and `envs/<env>/<layer>/`, one state per layer, partial backend | Known to the author; scales to staging and prod without restructuring |
| D11 | 2026-09-21 | A model-free `inspect` mode in the Runtime | Free and instant answers whenever no model is needed; the deterministic baseline for testing the narrative |
| D12 | 2026-09-23 | **The public web service lives in its own repository**, not here. This repository keeps the library, the CLI, the agent, the Runtime container and the Terraform that deploys that Runtime. The service repository owns the front end, the user layer (history, quota, private datasets), the sign-in and the infrastructure of the public instance | Four independent reasons: a package that lives alone with its only consumer never earns a clean API, and a separate consumer proves it; a permissive library meant to be vendored has different obligations from a deployment tied to one AWS account, one database schema and one domain; the two READMEs answer different questions ("how do I audit my dataset" and "how is this instance deployed"); and the two change on different rhythms. The boundary is sharp: **the Runtime is this tool's deployable, the service is a client of it**, so anyone can deploy the auditor for their private datasets without any of the service |
| D13 | 2026-09-23 | The product name stays **demosift** for users, on both sides; the service repository is named `demosift-web` (created and specified 2026-09-23 at `~/Sites/demosift-web`; canonical domain `demosift.io`) | Two brands for one thing confuse adoption; the service is how most people will meet the tool, since the CLI needs Python and a terminal. `demosift.io`, `.dev`, `.com`, `.app` and `.ai` were all unregistered on 2026-09-23 |
| D14 | 2026-09-25 | **The AWS account is the author's existing standalone account**, the one already configured in the CLI; not a new account, not an organization | A new account would sit under the fraud holds new accounts get (Route 53 Domains refused a registration on this very day for that reason); an organization has nothing to separate for one person's free tool: one account, one bill, one budget alarm. The account id lives only in the gitignored `backend.hcl` and `terraform.tfvars`, never in a committed file of this public repository. Two operator facts recorded with it: the CLI's default region is not the project's, so every `aws` command takes `--region eu-central-1` or a dedicated profile; and the operator identity is an IAM user with long-lived keys, acceptable on one laptop with MFA enabled, and the thing to replace with IAM Identity Center the day a second account or a second person appears. Neither fact touches the rule that the CI and the application never hold a static key |
| D15 | 2026-09-25 | **No infrastructure in this repository.** The Terraform that deployed the Runtime (`budget` and `runtime` modules, one root), `.tflint.hcl`, the Terraform CI job and the `tf-*` targets moved to `demosift-web`. Supersedes the part of D12 that kept "the Terraform that deploys that Runtime" here | A tool repository has no business deploying itself. Its users install it and run the CLI; its contributors were paying tflint, trivy and `terraform validate` on every pull request for files they would never touch; and a `budget` module was the tell that operations had leaked into a library. The self-hosting D12 imagined, a Runtime in someone else's AWS account, is speculative; the realistic self-host is `pip install` or `docker run`, and both need only the image. The artefact that crosses from tool to deployment is that image, documented by its contract (`docs/01` §5); how it is run, in which account, with which alarms, is the deployment's question. If someone asks for an AgentCore deployment example for themselves, it becomes an issue and then a `deploy/` example, not before |
| D16 | 2026-09-25 | **The fixed audits are Lambdas; Code Interpreter is for improvised code only.** Closes the open question of `docs/01` §3 | Deterministic, tested, unchanging code has nothing to do in a sandbox built for executing code the agent improvises. The numeric and visual audits are pure functions of this library, run as Lambdas behind the Gateway by the public instance; the agent container stays thin and does not crunch (`docs/01` §4). Code Interpreter keeps the one job it is for, the free-form question on a finished report, which arrives with that conversation |
| D17 | 2026-09-25 | **The image is instrumented with OpenTelemetry and published to GHCR on every version tag.** The Dockerfile runs the server under `opentelemetry-instrument` from `aws-opentelemetry-distro`, with `/ping` excluded from tracing; a `release` workflow builds the `linux/arm64` image on a `v*` tag and pushes `ghcr.io/christophe17/demosift:<version>` and `:sha-<12>` as plain manifests. A deployment copies the image by digest into its own registry and never rebuilds it; the version tag is the only thing it passes to Terraform | Reading the course capstone exposed the gap: the container contract promised traces in AgentCore Observability, but nothing in the image emitted any; AgentCore supplies the exporter configuration, the application must carry the instrumentation. Publishing from this repository's CI is what "build once" means: the artefact is born where the code is tested, and deployments promote it instead of rebuilding from a checkout. Locally the exporter is disabled with `OTEL_SDK_DISABLED=true`, so `make docker-run` stays quiet. One manual step, once: the GHCR package is private by default and is made public in the package settings |
| D18 | 2026-09-27 | **The library has no agent and no model.** `agent.py`, `runtime.py`, Strands, the AgentCore SDK and the OpenTelemetry distribution are removed; the package is the deterministic auditor and its CLI, its public surface is `demosift/__init__.py`, and it is released as a wheel and a command-line image. The assistant moves to the hosted instance's repository, where it becomes what an agent is for: helping a user understand and act on an audit, with this library's functions as its tools. Supersedes the parts of D5, D8, D11 and D17 that placed an agent, a Runtime entrypoint and their instrumentation here | Asked plainly whether the agentic approach brought anything to the tool, the honest answer was no: every milestone is deterministic or batch inference (the visual audit is a model used as a classifier), and the only genuinely agentic behaviour, deciding what to compute in answer to an open question, is a conversation about a finished report, which is a feature of the service. The "multi-agent auditor" framing came from the constraint the project was born under, not from the problem. Splitting sharpens both halves: a roboticist trusts a deterministic, testable auditor; the instance's assistant uses AgentCore for what it is for. Measured effect: 139 packages in the lock file to 40, none of them a cloud or agent SDK; the image from 590 MB to 524 MB; 14 tests, 93 % coverage |
| D19 | 2026-09-27 | **The terminal rendering is hand-written; Rich is not adopted.** `to_text` in `report.py`: aligned columns, the last column wrapped to the width, ANSI styles through `click.style`, control characters from the dataset replaced. The CLI renders text on a terminal and keeps Markdown when piped; `--format` makes the choice explicit and `NO_COLOR` is honoured | The stack rule says nothing else runs at runtime, and D18 had just brought the lock file to 40 packages; Rich would add four (rich, markdown-it-py, mdurl, pygments) to render a Markdown string it centres and pads to the full width, and in the trial it truncated the check names that carry the camera key. Two hundred lines, tests included, buy the same legibility with a deterministic fixed-width output the fixture tests pin. Revisited if a second need for a terminal library appears, progress on the milestone 1 downloads for instance |
